## 1. 问题与目标

长课程生产不是一次模型调用。它需要明确受众和范围、规划课程蓝图、按批次写作、维护跨章连续性、执行语言与语义审校、构建静态页面，并在关键决策处由人确认。若依赖长对话搬运上下文，模型失败、上下文变长或质量问题出现时，操作者很难知道应从哪里恢复。

本项目的目标是让课程从需求到发布成为一个可观察、可恢复、可审计的过程：

- 用确定性 Workflow 规定步骤、循环、停止条件与人工闸门；
- 只在理解、规划、写作和审校节点调用模型；
- 将正文、工作区文件、事件、Artifact 和质量证据分别持久化；
- 让质量问题形成带证据的定向修复任务，而不是整课重写；
- 始终由用户确认课程方向和最终发布。

一句话定位：**一个由人工掌握发布权的、本地优先课程生产 Agent。**

## 2. 用户与场景

| 用户 | 场景 | 成功结果 |
| --- | --- | --- |
| 课程创建者 | 新建课程、补充资料、批准任务与蓝图 | 获得可继续编辑与发布的课程目录 |
| 内容审校者 | 查看章节、质量报告与修复结果 | 能定位问题证据并决定是否继续修复 |
| Agent 学习者 | 阅读代码、运行样例、观察一次 Run | 理解 Agent、Workflow、Worker、Artifact 与质量门的协作 |
| 本地维护者 | 配置模型、检查失败与恢复 Run | 能从事件、Trace、checkpoint 和课程文件判断下一步 |

## 3. 核心工作流

界面展示七个阶段：

```text
intake → mission → blueprint → batch_plan → generation → quality → release
```

- **intake**：收集标题、slug、受众、学习目标、范围、来源策略、章节数和有效字符约束，初始化课程 Workspace 与 Run。
- **mission**：将输入整理为可验收的任务定义，等待人工批准、修改或停止。
- **blueprint**：规划模块、章节、学习成果、依赖与生成批次；来源研究在该规划流程中作为受控子步骤执行。
- **batch_plan**：沿模块和依赖边界分批，使失败只影响当前批次。
- **generation**：为每章组装 Context Pack，生成 Markdown，执行 `humanizer-zh`、语义审校和连续性提取。
- **quality**：汇总结构、内容、语言、语义与集成证据，生成 RepairTask；预算耗尽或证据冲突时转人工处理。
- **release**：展示整课质量结论，由用户决定发布或继续修复。

## 4. 课程与运行数据

课程文件位于 `courses/<slug>/`。`workspace/` 保存任务定义、来源、规格、蓝图和上下文；`lessons/` 的 Markdown 是学生正文事实源；HTML 是可重新构建的发布产物；`quality/` 保存当前质量快照与批次结果。

根目录 `.course-agent/` 在本机运行时创建：`agent.db` 保存 Run、Command、Event、Artifact、RepairTask 与 Trace，`checkpoints.db` 保存 LangGraph checkpoint。它们不进入 Git；课程正文不会只存在数据库或聊天记录中。

## 5. 质量与人工边界

课程通过不等于模型已经输出文本。章节和批次至少经过：

1. 有效字符与中文语言门：`humanizer-zh` 分数不得低于 `45/50`；
2. 教学语义与事实审校：结果必须为 `ready`；
3. 跨章连续性：将本章摘要和未闭环问题写入 continuity ledger；
4. Source Contract：检查 Markdown 结构、引用与学生页面的信息边界；
5. 静态构建与确定性校验：将 Markdown 重建为课程页面并验证产物。

自动修复只处理有明确证据和成功判据的问题，优先段落或小节级别。连续三轮同类 blocker 未解决时，系统停止自动返工并等待人工判断。

## 6. 范围与非目标

**包含**：本地课程创建、Workspace、来源登记、课程蓝图、分批生成、章节编辑、质量闭环、Run 恢复、Provider 设置和静态课程构建。

**不包含**：登录/权限、多租户、协作编辑、LMS/支付、视频或配音生成、自动公网发布、通用 Agent Builder、多机调度与云基础设施。

## 7. 学员阅读建议

1. 先阅读本文，理解产品为何需要 Workflow 与人工闸门。
2. 阅读 [FE-TD.md](FE-TD.md)，从用户操作和界面状态进入代码。
3. 阅读 [BE-TD.md](BE-TD.md)，沿 API → Command/Worker → LangGraph → 课程文件追踪一次 Run。
4. 最后结合 `README.md` 的启动命令运行项目，并观察内置 Obsidian 样例课程。
